Templates

Pacotes

Conexões

Tipos de conexão descritos só como dado: o servidor, o jeito de entrar e o que ele deixa ler e escrever. Nenhum traz código para rodar na sua máquina.

Contribuir

Como publicar uma conexão ou template

Qualquer pessoa pode propor um item. Ele entra por pull request no repositório do catálogo, passa pela validação automática e pela revisão de quem mantém, e só depois do merge chega ao índice que o app lê.

Guia de contribuição Repositório do catálogo
  1. Prepare o arquivoCada item é um JSON em templates/, packages/ ou connections/, com nome e descrição em inglês e em português. Template e pacote saem do próprio app, pela exportação, que já limpa o que é seu. Conexão é só dado: servidor https, jeitos de entrar, campos, gatilhos e ações que o app já conhece.
  2. Confira o que não podeNada de comando, npx, uvx ou script baixado. Nomes de pessoa, time, canal, host e repositório precisam ser genéricos. Os ids das conexões oficiais, como github e slack, só quem mantém publica.
  3. Rode o validadorCom Node 20 ou mais novo, npm ci --ignore-scripts, npm run validate e npm test. Cada erro diz o arquivo e o campo.
  4. Abra o pull requestA CI valida de novo e quem mantém revisa. A cada mudança, o campo version do item sobe.
  5. Depois do mergeA CI assina o índice e publica. A entrada aparece aqui e no app só a partir daí.
